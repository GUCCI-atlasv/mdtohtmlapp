01

Headings

CommonMark

ATX headings use one to six hash marks followed by a space. Setext underlines provide alternate H1 and H2 syntax.

Syntax

# Page title

## Section title ##

Setext heading
--------------

Static preview

Page title

Section title

Setext heading

Exact HTML

<h1 id="page-title">Page title</h1>
<h2 id="section-title">Section title</h2>
<h2 id="setext-heading">Setext heading</h2>

Gotchas

  • `#Title` has no required space, so CommonMark leaves it as plain text.
  • Closing hashes in `## Title ##` are valid and are removed from the heading text.
  • Seven or more opening hashes do not make a heading.
  • `===` under text makes H1 and `---` under text makes H2; a standalone `---` is a horizontal rule. One blank line changes the result.
  • Heading IDs are renderer behavior, not Markdown syntax. GitHub creates slugs; marked itself does not.

Compatibility

ATX and Setext headings work in CommonMark and GFM. This site adds deterministic IDs after marked renders the heading.

02

Bold and italic

CommonMark

Use one delimiter for emphasis, two for strong emphasis, and three for both.

Syntax

*italic* and **bold** and ***both***

Use `snake_case_name` for code.

Static preview

italic and bold and both

Use snake_case_name for code.

Exact HTML

<p><em>italic</em> and <strong>bold</strong> and <em><strong>both</strong></em></p>
<p>Use <code>snake_case_name</code> for code.</p>

Gotchas

  • CommonMark prevents intraword underscores from adding emphasis, but stars can: `a*b*c` emphasizes the b.
  • Intraword strong emphasis works with stars in `un**bel**ievable`, but not with underscores.
  • Spaces just inside the delimiters make `** text **` fail.
  • `***x***` becomes nested emphasis and strong markup; exact nesting is parser-defined.
  • Wrap variable names and filenames in backticks.

Compatibility

Star and underscore emphasis are supported by CommonMark, GFM, and this converter.

03

Line breaks

CommonMark

A single newline is soft. Use a visible trailing backslash for a hard break, or a blank line for a new paragraph.

Syntax

A visible hard break\
starts this line below.

A blank line starts a new paragraph.

Static preview

A visible hard break
starts this line below.

A blank line starts a new paragraph.

Exact HTML

<p>A visible hard break<br>starts this line below.</p>
<p>A blank line starts a new paragraph.</p>

Gotchas

  • A single newline is a soft break; HTML collapses it to whitespace inside the same paragraph.
  • Two trailing spaces also produce `<br>`, but editors often delete invisible trailing whitespace on save.
  • A trailing backslash produces `<br>` and is the recommended, visible form.
  • A blank line starts a new paragraph.
  • This converter uses `breaks: false`, following CommonMark. GitHub comments may turn every newline into a break, while README files do not.

Compatibility

Hard breaks and paragraph breaks are CommonMark. Automatic breaks for every newline are a renderer option and are disabled here.

04

Lists

CommonMark

Use hyphens, plus signs, or stars for unordered lists and a number plus period for ordered lists.

Syntax

3. First rendered item
4. Second item
   - Nested item
   - Another nested item

Static preview

  1. First rendered item
  2. Second item
    • Nested item
    • Another nested item

Exact HTML

<ol start="3">
<li>First rendered item</li>
<li>Second item<ul>
<li>Nested item</li>
<li>Another nested item</li>
</ul>
</li>
</ol>

Gotchas

  • Numbers need not be sequential, but the first number controls the `<ol start>` value.
  • Nested content must align with the parent item's content start: two spaces after `- `, three after `1. `.
  • Mixing tabs and spaces commonly flattens nested lists; too much indentation can create a code block.
  • Blank lines between items create a loose list whose `<li>` contents are wrapped in `<p>`.
  • A prose line such as `2024. That year` can become a list; write `2024\.` to escape it.
  • Leave a blank line between a paragraph and the list for portable rendering.

Compatibility

Ordered, unordered, nested, tight, and loose lists work in CommonMark and GFM.

05

Task lists

GFM

GFM recognizes checkbox markers at the start of list-item content.

Syntax

- [x] Ship the feature
- [ ] Write the release notes

Static preview

  • Ship the feature
  • Write the release notes

Exact HTML

<ul>
<li><input checked="" disabled="" type="checkbox"> Ship the feature</li>
<li><input disabled="" type="checkbox"> Write the release notes</li>
</ul>

Gotchas

  • The marker must be `- [x]` or `- [ ]`; `-[x]` is missing the list-marker space.
  • A standalone `[x]` is not a task item.
  • The generated checkbox is disabled, so it cannot be clicked in static HTML. Platforms add interactivity separately.
  • A bare checkbox has no explicit label, so use task lists cautiously in formal accessible documents.

Compatibility

Task lists are GFM, not core CommonMark. marked emits disabled checkbox inputs.

06

Links

CommonMark

Inline, titled, reference, and angle-bracket links cover most destinations.

Syntax

[Converter](https://mdtohtml.app/ "Free converter")

[Reference link][tool]

[tool]: https://mdtohtml.app/markdown-cheatsheet/

Static preview

Converter

Reference link

Exact HTML

<p><a href="https://mdtohtml.app/" title="Free converter">Converter</a></p>
<p><a href="https://mdtohtml.app/markdown-cheatsheet/">Reference link</a></p>

Gotchas

  • URLs containing spaces need `%20` or angle brackets, as in `[file](<my file.pdf>)`.
  • A closing parenthesis in a URL must be escaped as `\)`.
  • Bare URL autolinking is GFM. Core CommonMark uses `<https://example.com>`.
  • Markdown has no native `target="_blank"` syntax; raw HTML may be sanitized by a platform.
  • Relative URLs resolve from the rendered page, so moving or converting the file can break them.
  • DOMPurify removes unsafe protocols such as `javascript:` in this converter.

Compatibility

Inline and reference links are CommonMark. Bare URL autolinking is GFM and enabled here.

07

Images

CommonMark

Markdown image syntax needs useful alt text. Raw HTML is required when explicit dimensions and lazy loading matter.

Syntax

<a href="/" title="Open the Markdown converter"><picture><source srcset="/assets/demo/landscape.webp" type="image/webp"><img src="/assets/demo/landscape.jpg" alt="Tabby kitten on a desk beside a code-print mug, with the mdtohtml.app logo and a Markdown-to-HTML file icon" title="Self-hosted demo image" width="600" height="400" loading="lazy"></picture></a>

Static preview

Exact HTML

<p><a href="/" title="Open the Markdown converter"><picture><source srcset="/assets/demo/landscape.webp" type="image/webp"><img src="/assets/demo/landscape.jpg" alt="Tabby kitten on a desk beside a code-print mug, with the mdtohtml.app logo and a Markdown-to-HTML file icon" title="Self-hosted demo image" width="600" height="400" loading="lazy"></picture></a></p>

Gotchas

  • The standard syntax is `![alt](src)` and alt text is essential for accessibility.
  • Markdown has no standard image-size syntax. `![alt](img.png =100x)` is renderer-specific; use an HTML `<img width height>` when size matters.
  • Make a clickable image with `[![alt](img.png)](https://target)`.
  • A `<picture>` with a WebP `<source>` and a JPG `<img>` fallback survives conversion, so modern browsers get the smaller file and older ones still see the image.
  • Relative paths are the leading cause of broken images after a standalone HTML file moves. Use an absolute URL or distribute the image directory with the HTML.
  • Encode spaces in filenames as `%20`.
  • If the image file is missing, browsers keep the descriptive `alt` text as the fallback — write alt for readers, not as a caption.

Compatibility

Images and linked images are CommonMark. Dimensions, lazy loading and the `<picture>`/`<source>` fallback shown here are safe raw HTML retained by this converter.

08

Code

CommonMark

Backticks mark inline code; fenced or indented blocks preserve code as literal text.

Syntax

Use ``a ` b`` when code contains a backtick.

```js
const html = MDH.renderMarkdown(markdown).html;
```

Static preview

Use a ` b when code contains a backtick.

const html = MDH.renderMarkdown(markdown).html;

Exact HTML

<p>Use <code>a ` b</code> when code contains a backtick.</p>
<pre><code class="language-js">const html = MDH.renderMarkdown(markdown).html;
</code></pre>

Gotchas

  • Use double backticks around inline code that contains a backtick.
  • Fences may use backticks or tildes; a language label creates a class such as `language-js`.
  • Syntax highlighting is not Markdown. The class is only a hook for highlight.js, Prism, Shiki, or similar tools.
  • Four-space indentation also creates a code block and is easy to trigger accidentally inside lists.
  • HTML inside code blocks is escaped, for example `<` becomes `&lt;`.
  • Indent a fenced block to keep it inside a list item.
  • To demonstrate triple backticks inside a block, fence the outer block with four backticks.

Compatibility

Inline code, indented code, and fenced code are CommonMark. Language-based highlighting is renderer-specific.

Blockquotes

CommonMark

Prefix quoted content with `>`; blockquotes can contain most other block elements.

Syntax

> A quoted paragraph.
>
> - A list inside the quote
> - A second item
>
>> A nested quote

Static preview

A quoted paragraph.

  • A list inside the quote
  • A second item

A nested quote

Exact HTML

<blockquote>
<p>A quoted paragraph.</p>
<ul>
<li>A list inside the quote</li>
<li>A second item</li>
</ul>
<blockquote>
<p>A nested quote</p>
</blockquote>
</blockquote>

Gotchas

  • A lazy continuation line without `>` can still be absorbed into the quote.
  • Use a line containing only `>` to separate paragraphs inside a quote.
  • Use `>>` for a nested quote.
  • Lists, code blocks, and headings can all appear inside blockquotes.

Compatibility

Blockquotes and nested blockquotes are supported by CommonMark and GFM.

Tables

GFM

A header row and delimiter row create a GFM table; colons control alignment.

Syntax

| Syntax | Result | Support |
|:--|:--:|--:|
| `**bold**` | **bold** | GFM |
| `a\|b` | a\|b | Escaped pipe |

Static preview

Syntax Result Support
**bold** bold GFM
a|b a|b Escaped pipe

Exact HTML

<table>
<thead>
<tr>
<th align="left">Syntax</th>
<th align="center">Result</th>
<th align="right">Support</th>
</tr>
</thead>
<tbody><tr>
<td align="left"><code>**bold**</code></td>
<td align="center"><strong>bold</strong></td>
<td align="right">GFM</td>
</tr>
<tr>
<td align="left"><code>a|b</code></td>
<td align="center">a|b</td>
<td align="right">Escaped pipe</td>
</tr>
</tbody></table>

Gotchas

  • The delimiter row such as `|---|---|` is mandatory; without it, the table stays text.
  • Use `:---` for left, `:---:` for center, and `---:` for right alignment.
  • Escape every pipe inside a cell as `\|`, even inside inline code.
  • Leading and trailing pipes are optional.
  • The header determines the column count; extra cells are discarded.
  • GFM tables have no colspan, rowspan, or multiline cell syntax. Use `<br>` for a visual line break.
  • Leave a blank line before a table for portable rendering.

Compatibility

Tables are GFM, not core CommonMark. marked has GFM enabled on this site.

Strikethrough

GFM

Double tildes are the most portable GFM form for deleted text.

Syntax

The old value is ~~deprecated~~ replaced.

Static preview

The old value is deprecated replaced.

Exact HTML

<p>The old value is <del>deprecated</del> replaced.</p>

Gotchas

  • `~~text~~` becomes `<del>`.
  • GFM can accept one or two tildes in some contexts, but many parsers only recognize two. Always use double tildes.
  • Core CommonMark does not support strikethrough and leaves the delimiters as text.

Compatibility

Strikethrough is GFM and enabled here; it is unsupported by core CommonMark.

Horizontal rule

CommonMark

Three or more spaced or unspaced hyphens, stars, or underscores create a thematic break.

Syntax

Paragraph above.

---

Paragraph below.

Static preview

Paragraph above.

Paragraph below.

Exact HTML

<p>Paragraph above.</p>
<hr>
<p>Paragraph below.</p>

Gotchas

  • `---`, `***`, and `___` all create a rule when used as a block.
  • A `---` immediately below text is parsed as a Setext H2 underline, not `<hr>`. Leave a blank line before the rule.

Compatibility

Thematic breaks are CommonMark and work in GFM and this converter.

13

Escaping

CommonMark

A backslash makes ASCII punctuation literal instead of starting Markdown syntax.

Syntax

\*not italic\* and \# not a heading

A literal less-than sign: &lt; and copyright: &copy;

Static preview

*not italic* and # not a heading

A literal less-than sign: < and copyright: ©

Exact HTML

<p>*not italic* and # not a heading</p>
<p>A literal less-than sign: &lt; and copyright: ©</p>

Gotchas

  • Backslash escapes work for punctuation including `\* \_ \# \` \[ \] \( \) \| \~ \\`.
  • Literal `<` and `&` are encoded as entities when needed.
  • Named HTML entities such as `&copy;` pass through as their represented character.

Compatibility

Backslash escapes and HTML entities are part of CommonMark.

14

Raw HTML

CommonMark

CommonMark permits raw HTML, but safe renderers sanitize dangerous tags, attributes, and URLs.

Syntax

<div class="note">Plain <strong>HTML</strong>, not **Markdown emphasis**.</div>

<button onclick="alert(&#39;unsafe&#39;)">Sanitized button</button>

<script>alert(&#39;removed&#39;)</script>

Static preview

Plain HTML, not **Markdown emphasis**.

Exact HTML

<div class="note">Plain <strong>HTML</strong>, not **Markdown emphasis**.</div>

<p><button>Sanitized button</button></p>

Gotchas

  • CommonMark and GFM allow embedded HTML, but platforms commonly sanitize it. This site uses DOMPurify to remove scripts and event handlers.
  • Markdown is not parsed inside an HTML block: `<div>**bold**</div>` keeps the asterisks.
  • Emoji shortcodes such as `:smile:` are a GitHub platform feature, not CommonMark.
  • Footnotes such as `[^1]` are parser extensions and are not supported by marked 12 in this configuration.

Compatibility

Raw HTML is accepted by CommonMark, GFM, and marked; the exact allowlist is controlled by DOMPurify.

Symptom → cause → fix

Markdown troubleshooting

Fourteen frequent conversion failures, named the way they appear when you are debugging.

01

My line breaks disappear and several lines become one paragraph

Cause: A single newline is a soft break.

Fix: Add a trailing backslash for `<br>`, or a blank line for a new paragraph.

02

Two trailing spaces still do not make a line break

Cause: The editor removed invisible trailing whitespace on save.

Fix: Use a visible trailing backslash instead.

03

My table displays as one line of plain text

Cause: The required delimiter row is missing.

Fix: Add `|---|---|` and leave a blank line before the table.

04

My table breaks in the middle

Cause: A cell contains an unescaped pipe, possibly inside inline code.

Fix: Escape every cell pipe as `\|`.

05

My image is missing and only alt text remains

Cause: A relative path resolves from a different page after conversion.

Fix: Use an absolute URL or ship the image directory with the HTML.

06

A variable name becomes italic

Cause: Emphasis delimiters were interpreted as formatting.

Fix: Wrap identifiers in backticks or escape punctuation.

07

My nested list is flattened

Cause: Indentation is short or tabs and spaces are mixed.

Fix: Align child content with the parent item content start.

08

List items suddenly have large gaps

Cause: Blank lines made the list loose, so each item contains a paragraph.

Fix: Remove blank lines between items.

09

A mysterious horizontal line or heading appears

Cause: A `---` below text is a Setext heading underline; standalone it is a rule.

Fix: Put blank lines around a rule or use `***`.

10

`#Title` does not become a heading

Cause: CommonMark requires a space after the hashes.

Fix: Write `# Title`.

11

My task-list checkbox cannot be clicked

Cause: GFM output intentionally uses a disabled checkbox.

Fix: Treat it as status display; add application JavaScript for interaction.

12

Markdown works on GitHub but not elsewhere

Cause: The source uses GFM extensions or a different `breaks` option.

Fix: Check the compatibility table and prefer CommonMark forms.

13

Raw HTML or attributes disappear

Cause: DOMPurify removed unsafe markup.

Fix: Use equivalent Markdown or safe semantic HTML without scripts and event handlers.

14

Markdown inside an HTML tag is not formatted

Cause: Markdown is not parsed inside CommonMark HTML blocks.

Fix: Use pure Markdown or complete the formatting in HTML.

Practical answers

Frequently asked questions

Content for readers only; this page intentionally does not use FAQPage or HowTo structured data.

What Markdown flavor does this converter use?

It uses marked 12.0.0 with GitHub Flavored Markdown enabled and `breaks: false`, then sanitizes output with DOMPurify. Tables, task lists, strikethrough, fenced code, and bare URL autolinking work.

Why does the exact HTML include heading IDs?

After marked and DOMPurify run, the shared MdEngine assigns deterministic IDs to H1–H3 headings for tables of contents and direct links. IDs are renderer behavior, not part of CommonMark.

Can Markdown set image width and height?

Not in standard CommonMark. Use safe raw HTML with explicit `width`, `height`, and `loading="lazy"`, as the self-hosted image example does.

Why are task-list checkboxes disabled?

GFM represents task state with disabled checkbox inputs. GitHub or an application can add interaction, but static generated HTML is intentionally read-only.

Is raw HTML safe to paste?

The converter sanitizes output with DOMPurify, removing scripts, event handlers, and unsafe URLs. Still review generated HTML before publishing untrusted content.

Can I use this page without JavaScript?

Yes. Every reference, static preview, exact HTML sample, gotcha, compatibility note, troubleshooting fix, and FAQ is built into the page. JavaScript only powers live editing, copying, and Try it shortcuts.
